# Spec S4.1: DocumentChecklistAgent

For each matched scheme, assemble required-document checklist.

## Overview

The `DocumentChecklistAgent` takes the list of matched schemes generated by the `EligibilityMatcherAgent` and assembles an aggregated, deduplicated checklist of required documents across all eligible schemes. It will invoke the `get_scheme` MCP tool to retrieve the exact document requirements for each matched `scheme_id`.

## Dependencies

- Logical: `S2.3` (get_scheme tool), `S3.4` (Orchestrator delegation)
- Technical: `google-adk`

## Target Location

- [NEW] `app/agents/documents.py`
- [NEW] `tests/agents/test_documents.py`
- [MODIFY] `app/agents/orchestrator.py`

## Functional Requirements (FRs)

- **FR1: Fetch Scheme Documents**
  - **Inputs**: `SessionState.matches` (list of `MatchResult`s).
  - **Outputs**: Fetch the full scheme data using the `get_scheme` MCP tool (or cached database equivalent) to get the required documents list for each scheme.
  - **Edge Cases**: If `get_scheme` fails for one scheme, log the error but proceed with others.
- **FR2: Assemble and Deduplicate Checklist**
  - **Inputs**: Lists of documents from multiple schemes.
  - **Outputs**: A flat, deduplicated list of strings representing the required documents written to `SessionState.checklist`.
  - **Edge Cases**: If no matches are present, return an empty checklist without invoking the tool. Handle slight terminology differences if using LLM to normalize (or just exact string matching if structured).

## Test-Driven Requirements (TDD)

- `test_document_checklist_success`: Mock multiple schemes returning overlapping documents. Verify the final `SessionState.checklist` is deduplicated.
- `test_document_checklist_empty_matches`: Verify that if `SessionState.matches` is empty, it returns an empty checklist immediately.
- `test_document_checklist_handles_tool_failure`: Simulate the `get_scheme` tool failing for one of the schemes and ensure it gracefully handles the others.
