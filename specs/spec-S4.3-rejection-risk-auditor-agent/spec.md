# Spec S4.3: RejectionRiskAuditorAgent

Critic loop: re-check each match against eligibility rules; flag weak/hallucinated eligibility; `max_iterations`, early-exit on pass. Quality guardrail.

## Overview
The `RejectionRiskAuditorAgent` acts as a quality guardrail within SchemeWayfinder. It is implemented as an ADK `LoopAgent` that critically evaluates the `MatchResult`s generated by the `EligibilityMatcherAgent`. It compares the `CitizenProfile` against the specific eligibility rules of the matched schemes to detect false positives, hallucinations, or weak matches. If a match is deemed risky, it flags or removes it, and can instruct the matcher to refine its search or simply update the state. The loop continues until all matches pass the audit or a `max_iterations` limit is reached.

## Functional Requirements (FRs)

- **FR1: Critic Evaluation**
  - **Inputs**: `SessionState.citizen_profile`, `SessionState.matches`
  - **Outputs**: Analyzes matches. If a match is hallucinated or weak, it is removed from the matches list and added to a `SessionState.rejected_matches` list with a reason.
  - **Edge Cases**: If no matches exist, immediately pass/early-exit. 

- **FR2: Loop Control**
  - **Inputs**: Output of the critic evaluation.
  - **Outputs**: Controls the loop. If changes were made to the match list, it triggers another iteration (if we were feeding back to matcher) or simply exits as a filtering step. *Note*: Given the design, it might just act as a filter that runs once, but the spec asks for a `LoopAgent`. The loop will evaluate up to `max_iterations`. If the condition passes, early-exit.
